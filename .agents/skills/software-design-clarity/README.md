# software-design-clarity

A reusable software-design review skill inspired substantially by John Ousterhout's *A Philosophy of Software Design*.

The skill focuses on reducing cognitive complexity through deep modules, information hiding, meaningful abstraction boundaries, strategic programming, deliberate state design, restrained configuration, and consistent terminology.

It is intended for:

- coding agents;
- human code/design review;
- architecture review;
- refactoring;
- PR review;
- project handovers.

The skill is advisory rather than a static enforcement mechanism.

It complements tools such as linters, architecture dependency checkers, type systems, and tests.

## Files

- `SKILL.md` — compact operational instructions for agents
- `references/principles.md` — fuller conceptual summary
- `references/design-smells.md` — common warning signs
- `references/review-questions.md` — practical review checklist
- `references/examples.md` — contrasting examples
- `references/bibliography.md` — source attribution/bibliographic reference
- `templates/design-review.md` — reusable review template
