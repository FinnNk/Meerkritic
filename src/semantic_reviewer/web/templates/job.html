How to assess the fields
FieldQuestion to answer
Issue statementDoes it faithfully describe the concern, without claiming more than the source supports?
Actionable concernDoes the comment identify something a developer could address? Use yes, no or uncertain.
GeneralisableCould the concern apply beyond this example? This does not validate a general rule.
CategoriesWhich broad engineering concerns does the source describe?
Impact scope (scope)Choose the smallest affected unit supported by the evidence: expression, statement, function, class, file, module or repository. Use unknown if the affected extent is unclear. Searching repository history does not itself establish repository-wide impact.
Candidate rule (proposed_invariant)What condition does this example suggest should hold? Use null if none is justified. Put your additional advice in notes and attribute it to yourself.
Applicability limits (exclusions)What known exceptions limit the concern or rule? Use an empty list if none are identified. Put missing evidence and investigation needs in notes.
Evidence quotesDo the exact quoted words support the claim? Matching text alone does not establish correctness.
