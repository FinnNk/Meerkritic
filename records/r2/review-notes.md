## Aggregate and design clarity

Complexity introduced: one fixed sampling/curation policy and its external file format.
Complexity removed: manual repetition of seeded ordering, eligibility, caps and progress.
Module depth: one domain module hides these rules behind sample/progress operations;
the CLI owns bounded file I/O and immutable publication. No forwarding service layers.
Knowledge leakage: callers need original bytes, explicit evidence and exact plan; they
need not implement sampling. The domain has no filesystem, web, database or MAF types.
Layer quality: source ordering is separately reviewable; CLI/evidence workflow stays
with its tests and operational guide. No schema-per-class or speculative experiment API.
Tactical cases: EDR-0001 is intentionally fixed, not a generic configurable research
framework. A changed study procedure must preserve its versioned source and evidence.
Highest-leverage simplification: keep comparison/rating tools a subsequent bounded
contract rather than expanding this preparation code into a research UI.

No unresolved implementation or boundary finding after inspection. Future protocol
changes must remain prospective. Do not present source checks, human reviews or
comparison tooling as delivered by this PR. Existing dependency deprecation warnings
remain visible in the raw logs; they are not failures or introduced changes.
