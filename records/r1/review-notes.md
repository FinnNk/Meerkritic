## Complexity introduced or removed

One shared action calculation replaces successful-only assumptions in consumers.
Selection version/null handling is the unavoidable representation cost of retaining
rejected failures without invented domain objects. Separate progress numerators
avoid confusing a human correction with model success.

## Module depth

AnnotationService hides validation/publication and durable decision semantics.
SelectionService owns evidence reconciliation. Callers request actions or freezes;
they do not parse runtime telemetry to decide admissibility.

## Knowledge/dependency leakage

Web knows how to display the retained draft, not how to classify eligibility.
SQLite knows terminal/publication identity, not interpretation semantics. No MAF,
provider/model or database types enter domain logic. Typed architecture delta adds
no modules, contracts, imports or boundary exceptions; existing interface shapes change.

## Layer quality

No pass-through repair layer was added. Existing boundaries perform distinct work:
domain schema/grounding, application eligibility/provenance, storage transactions,
web interaction. Model execution is untouched.

## Tactical special cases

Legacy successful-body compatibility is an existing supported contract, not a
blanket fallback. New failed bodies still require explicit job identity, semantic
failure classification, retained bounded text and matching error. Nullable data is
restricted to rejected exclusions under a versioned snapshot contract.

## Highest-leverage simplifications

Reuse the annotation store, publication owner and event transaction. No separate
repair job lifecycle, duplicate index or automatic correction is justified. No
further material design issue found in the inspected change. This does not claim
independent review, a general UI redesign or research suitability of any input.
